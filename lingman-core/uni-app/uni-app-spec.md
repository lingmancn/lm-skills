# Lingman uni-app 开发规范

> 适用于 Lingman 体系下基于 Vue 3、TypeScript 与 uni-app 的移动端项目。
> 本文只维护跨项目稳定规则；版本、脚本、环境地址、应用标识和业务常量必须从目标项目实时读取。

## 使用顺序

1. 读取目标项目的 `package.json`、页面配置、Manifest 配置、构建配置和环境配置。
2. 搜索已有页面、组件、请求层、Store、Hooks 与工具函数，优先复用。
3. 若项目为 p708 或采用相似架构，参考 [p708-verified-patterns.md](p708-verified-patterns.md)，但仍以当前源码为准。
4. 运行、调试和构建按 [tooling-guide.md](tooling-guide.md) 执行。
5. 管理后台 Web 继续使用 [frontend-spec.md](../frontend/frontend-spec.md)，禁止把 Element Plus、`@lingman/yd`、`<Table>`、`<Dialog>` 等规则套入 uni-app。

## 项目事实探测

开发前至少确认：

- Vue、uni-app、Vite、TypeScript、Pinia、UI 库和样式方案；
- 包管理器、Node 版本和真实 scripts；
- 页面是直接维护 `pages.json`，还是由 `definePage()`、配置文件和插件生成；
- Manifest 是直接维护还是生成；
- API、请求桥接、Token、登录跳转和统一错误处理；
- 主包、分包、TabBar 与默认登录策略；
- 目标交付平台，以及哪些平台必须保持兼容；
- 自动生成目录、必须提交的生成物和禁止手改文件。

禁止根据模板经验编造目录、命令、接口、环境变量或平台能力。

## 页面与路由

- 页面元信息遵循项目现有机制；使用 `definePage()` 的项目不得把生成后的 `pages.json` 当主要编辑入口。
- TabBar 页面使用 `uni.switchTab()`；普通页面按场景使用 `navigateTo`、`redirectTo`、`reLaunch` 或项目路由封装。
- 自定义导航栏同时处理状态栏、安全区、占位和无历史记录时的返回兜底。
- 页面首次加载、再次显示、隐藏和卸载分别使用合适的 uni-app 生命周期，不能把页面生命周期与 Vue 组件生命周期混用。
- 页面隐藏或卸载时清理定时器、监听器、请求序号、媒体实例、长连接和其他副作用。
- 平台专属 API 使用条件编译或项目适配层，禁止在跨端路径直接使用 `window`、`document`、`wx` 等平台对象。

## API 与请求

- 先探测项目是否存在自动 API 体系；若存在，业务代码优先调用自动生成对象。
- 自动生成目录及其配套类型/元数据禁止手工修改；接口缺失时修正后端契约或生成配置后重新同步。
- 自动 API 与 uni-app 请求层之间复用项目已有桥接，禁止为了单个页面另建 axios/fetch 客户端。
- 页面不得自行拼接服务基地址、Token、租户头、加密头或公共错误提示。
- 返回类型优先从 API 方法推导，减少重复 VO：

```ts
const BizApi = ApiAppBizAppAdminApiAuto
type BizPage = Awaited<ReturnType<typeof BizApi.pageBizAppAdminApi>>
type BizItem = BizPage['list'][number]
```

- 后端 `Long` 可能超出 JavaScript 安全整数范围。路由参数、ID 比较和请求参数是否使用字符串，必须先查看项目现有类型和生成结果，不能无条件转为 `number`。
- 底层已统一提示的请求错误，页面不要重复弹同一提示；页面仍应维护可恢复的错误态和重试入口。

## 列表、搜索与异步竞态

分页列表通常需要区分：首屏加载、下拉刷新、加载更多、全部加载、首屏失败和加载更多失败。

- 新搜索、新筛选和刷新应重置页码、列表、总数和完成状态。
- 加载更多前检查 loading 与 finished，避免重复请求。
- 追加数据按稳定主键去重。
- 输入搜索使用防抖；立即搜索前取消待执行定时器，卸载时清理定时器。
- 搜索、筛选和刷新并发时使用请求序号、AbortController 或等价机制丢弃旧响应。
- 记录级启停、删除、提交使用记录级处理中状态，避免重复操作。
- 破坏性或关键状态变更必须二次确认。

## 状态管理

- 页面私有、生命周期短的 UI 状态留在页面或组件。
- 多页面共享、TabBar 缓存、认证、用户、字典、主题和业务角标等状态使用项目现有 Pinia 体系。
- 不在 Store 中持久化 DOM、PeerConnection、MediaStream、计时器等不可序列化资源。
- 持久化使用项目统一 storage 适配，不假定浏览器 `localStorage`。
- 退出登录或 Token 失效时，清理依赖当前用户身份的共享状态，避免账号切换后数据泄漏。
- 不随意删除项目为 APP 初始化时序设置的 Pinia 激活逻辑。

## 组件与 UI

- 优先使用项目已选的 uni-app UI 组件库，不重复封装已有基础组件。
- 两个以上页面复用，或具备独立状态和交互边界时，再抽取业务组件。
- Props、Emits 和 Expose 使用明确类型；事件名表达业务结果。
- UnoCSS、SCSS 和第三方组件覆盖方式遵循项目现状；局部样式使用 `scoped`，深层覆盖使用受限范围的 `:deep()`。
- 移动端尺寸优先沿用项目的 `rpx` 体系；数值尺寸型 UnoCSS 类必须显式带单位，包括零值，例如 `p-24rpx`、`top-0px`。
- 颜色优先使用项目语义变量或主题令牌，不在页面散落同义硬编码颜色。
- 动态生成的 UnoCSS 图标或类名需要加入 safelist，或改为静态可扫描写法。
- 固定头部、底部按钮、TabBar 页面必须处理安全区、可滚动区域和键盘顶起。

## 跨端媒体与资源释放

媒体能力必须按目标平台设计，不能把 H5 方案强行统一到 APP 或小程序。

- H5 WebRTC：关闭 PeerConnection，停止所有 MediaStreamTrack，清空 `srcObject`/`src`，取消计时器、请求和事件监听。
- APP 原生 video：页面隐藏或失活时停止播放，必要时通过条件渲染销毁组件；播放地址格式以项目真实后端能力为准。
- 其他平台：使用平台支持的 video 能力，并提供无法播放时的明确兜底。
- 切换媒体源或异步数据源时，防止旧异步结果覆盖当前结果。
- 自动播放被浏览器策略拒绝不等同于流地址失效。
- TabBar 缓存页除卸载外还必须考虑 `onHide`。

## 安全与敏感信息

- 不在代码、Skill、文档、日志或评测中复制环境密钥、Token、账号、AppID、证书或签名信息。
- 不记录完整 Authorization、加密请求体或敏感响应。
- 上传、定位、相机、相册、支付等能力必须检查目标平台权限和隐私要求。
- WebView URL、富文本和用户输入需要白名单、转义或项目既有安全处理。

## 开发完成检查

- [ ] 项目类型与目标平台已确认，未套用管理后台 Web 规范。
- [ ] 已优先复用现有页面、组件、API、Store、Hooks 和工具。
- [ ] 自动生成目录未手改，页面/Manifest 修改发生在真实配置源。
- [ ] TabBar 导航、登录路由和页面生命周期正确。
- [ ] 列表状态、搜索防抖、竞态与重复提交已处理。
- [ ] Wot/项目 UI 库、UnoCSS、主题变量和安全区符合项目规范。
- [ ] 定时器、监听器、媒体和长连接在隐藏/卸载时释放。
- [ ] 未泄露敏感配置，未经用户要求未创建测试文件。
- [ ] 已执行目标项目真实存在的静态检查；需要启动项目验收时先询问用户。
