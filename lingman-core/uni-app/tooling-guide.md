# uni-app 工具链与排障指南

> 适用于 uni-app CLI/Vite 项目的运行、环境、请求、生成配置和构建排障。
> 命令、目录、平台和 mode 必须从目标项目实时探测，本文不提供可直接盲跑的固定命令。

## 硬性规则

1. **启动前询问**：执行 dev/watch、启动前后端服务、浏览器、模拟器、真机、HBuilderX 或小程序开发者工具前，必须向用户确认，避免端口和进程冲突。
2. **真实 scripts 优先**：只运行 `package.json` 或项目构建文件真实存在的命令。
3. **包管理器不切换**：根据 `packageManager`、锁文件和 workspace 配置选择，不擅自生成第二种锁文件。
4. **先静态检查**：优先执行不会启动常驻服务的 typecheck、lint 和一次性 build；如果命令会打开 GUI、云打包或签名交互，也要先询问。
5. **不手改生成物**：构建产物、自动 API、自动页面和 Manifest 文件按项目规定维护。
6. **不泄露配置**：不得在回答、日志、Skill 或 eval 中回显密钥、Token、证书、签名或完整敏感环境值。
7. **报告真实结果**：未执行、命令不存在、平台 SDK 缺失或只完成静态推导时必须明确说明。

## 工程探测

### 项目根目录

确认实际 uni-app 应用所在目录，尤其注意 monorepo。常见证据：

- `package.json` 和锁文件；
- `@dcloudio/*` 依赖；
- `src/App.vue`、`src/main.*`；
- `pages.json`、`manifest.json` 或对应 TypeScript 配置源；
- `vite.config.*`、`uni.scss`、`uni_modules/`。

### 技术路线

读取依赖和构建配置确认：

- Vue 2 / Vue 3；
- Vite / webpack；
- TypeScript 是否启用；
- CLI / HBuilderX 工程；
- Pinia、UnoCSS、UI 组件库；
- pages/manifest 是否通过插件生成；
- 目标平台和现有条件编译写法。

### scripts 清单

完整读取 `package.json#scripts`，按以下维度整理：

| 类型 | 需要确认 |
|---|---|
| 开发 | 真实 script、目标平台、mode、是否常驻 |
| 构建 | 真实 script、目标平台、mode、产物性质 |
| 检查 | typecheck、lint、test 是否存在，是否会修改文件 |
| 同步 | API、页面、Manifest 等生成入口 |

若用户给出的命令不存在，应报告并继续寻找 workspace、HBuilderX 或项目文档中的真实入口，不能编造替代命令。

## 启动确认模板

准备启动前向用户说明：

```text
准备执行：<真实命令>
运行目录：<项目根目录>
目标平台：<H5 / APP / 小程序>
该操作会启动常驻进程或外部工具，可能占用端口。是否现在启动？
```

用户明确同意后才能执行。读取配置、typecheck、lint、普通一次性 build 通常不属于启动，但需先确认脚本没有隐藏副作用。

## 平台差异

### H5

重点检查：

- Vite `server.proxy`、请求前缀、target 和 rewrite 后的最终路径；
- history/hash 路由、base 和静态资源路径；
- CORS、Cookie、SameSite、HTTPS；
- 环境变量实际加载方式。

H5 开发代理只对浏览器开发服务器生效，不能解决 APP 或小程序真机网络问题。

### APP

重点检查：

- 真机/模拟器是否能访问目标后端；
- Android/iOS 权限、模块、网络安全和证书；
- APP 条件编译与原生插件；
- CLI build 输出是可安装包还是供 HBuilderX/云打包继续处理的资源。

不能把 `build:app` 一律描述成生成 APK/IPA，必须以项目实际流程为准。

### 小程序

重点检查：

- 具体平台 script 和输出目录；
- appid、权限、分包和包体限制；
- HTTPS、合法域名、端口和证书；
- 开发者工具和真机预览的差异。

开发者工具可用不代表真机可用，H5 proxy 也不能解决小程序合法域名问题。

## env、代理与 localhost

### 环境变量

读取目标项目存在的 `.env*`、构建 mode、`loadEnv`、`envPrefix` 和代码实际读取方式。确认：

- 哪个 script 加载哪个 mode；
- 变量前缀是否满足构建工具要求；
- 多个 env 文件的覆盖顺序；
- H5 与 APP/小程序是否使用同一地址策略；
- 客户端配置是否误放密码、私钥或服务端密钥。

不得仅凭文件名或常见变量名断言配置会生效。

### localhost

`localhost` 表示应用当前运行设备自身：

| 场景 | 含义 |
|---|---|
| 开发电脑上的 H5 | 开发电脑 |
| Android 模拟器 | 模拟器自身；部分模拟器有宿主机专用地址 |
| APP 真机 | 手机自身 |
| 小程序真机 | 手机自身 |

真机联调通常使用开发电脑局域网 IP，并检查同网段、后端监听地址、防火墙、VPN、HTTP/HTTPS 策略和合法域名。禁止把某个模拟器地址硬编码为全平台默认值。

## 401 与 Token 刷新排障

修改请求层前完整读取：

- `uni.request` 封装和拦截器；
- Token Store 与持久化；
- 登录、刷新 Token 和退出登录；
- 登录页跳转、redirect 和用户状态清理；
- 自动 API 所依赖的请求桥接。

### 响应分层

明确区分：

- 网络失败；
- HTTP 非 2xx；
- 业务码失败；
- 401/登录失效；
- 用户取消或请求中止。

进入 `uni.request.success` 不代表业务成功。

### 并发刷新检查

并发 401 至少满足：

1. 同一时刻只发起一次 refresh 请求；
2. 其他请求等待相同刷新结果；
3. 刷新成功后先更新 Token，再重放原请求；
4. 原请求最多自动重试一次，防止无限循环；
5. refresh/login 接口不能触发刷新自身；
6. 刷新失败时统一清理会话并拒绝所有等待请求；
7. 登录提示和跳转只执行一次；
8. 所有等待 Promise 最终都 resolve/reject；
9. 成功和失败路径都清理刷新状态；
10. 不记录完整 Token 或 Authorization。

可使用共享 `refreshPromise` 或项目现有等价 single-flight 机制。修复应尽量保持当前请求协议和桥接方式，不无故重写整个请求层。

## API 同步

执行接口同步前确认：

- 前端工程根目录；
- `lingman.config.json` 或项目真实 CLI 配置；
- CLI 是否已安装；
- Swagger 地址和后端文档是否最新；
- 自动生成目录的现有未提交变更。

规则：

- 在项目指定目录执行真实同步命令；
- 自动生成目录禁止手改；
- uni-app 适配写在自动目录外的请求桥接或薄封装；
- 生成后检查 git diff 和类型检查；
- 若 Swagger 需要启动/重启后端，必须先询问用户；
- CLI 未安装时报告缺项，不擅自全局安装；
- 不用手改生成文件绕过后端或 Swagger 未更新问题。

## pages 与 Manifest

先识别事实源：

- 直接维护 JSON；
- `pages.config.*`、`manifest.config.*`；
- 页面内 `definePage()`；
- Vite 插件或其他生成脚本；
- HBuilderX 可视化配置。

若存在生成式配置：

- 修改真实配置源；
- 使用项目真实生成流程；
- 生成后检查 JSON 与 git diff；
- 生成 JSON 是否提交以项目规则为准；
- 生成命令若为 watch/dev，执行前询问用户。

页面变更检查路径、主包/分包、TabBar、预加载和导航 API。Manifest 变更只修改目标平台节点，不覆盖 AppID、证书、签名或其他平台私有配置。

## 校验顺序

根据真实 scripts 选择：

1. 局部静态检查；
2. typecheck；
3. lint；
4. 受影响平台的一次性 build；
5. 检查页面/Manifest 生成结果和产物日志；
6. 需要运行态、模拟器或真机验证时，询问用户后执行。

默认不执行 `lint:fix`，因为它会产生额外修改。未经用户要求不新增测试框架或测试文件；可以运行项目已有测试命令。

## 失败处理

- 保留首个关键错误及上下文；
- 区分代码错误、环境缺失、依赖缺失、SDK/证书缺失和命令不存在；
- 不通过删除锁文件、清空配置或全量升级依赖碰运气；
- 安装依赖、修改全局环境或打开外部工具前说明影响；
- 修复后重新执行最小相关检查；
- 不能完成的验证如实写明原因。
